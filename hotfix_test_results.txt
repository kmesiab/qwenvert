releases. The hotfix code enforces checksum verification as a security 
requirement (fail-closed policy), which blocks installation.

Two options to resolve:

OPTION A: Calculate checksums from downloaded file (less secure)
  - Trust GitHub's HTTPS certificate instead of separate checksums
  - Verify Content-Length header matches expected size
  - Risk: Depends entirely on GitHub infrastructure

OPTION B: Skip checksum verification for ggml-org releases (not recommended)
  - Add fallback that skips verification if checksums unavailable
  - Risk: Reduces security posture

OPTION C: Use alternative source (recommended)
  - Check if ggml-org provides checksums in a different location
  - Check if repository settings have changed
  - Escalate to ggml-org maintainers

OPTION D: Host checksums ourselves (most secure)
  - Calculate official checksums once per release
  - Host on qwenvert infrastructure
  - Provides both security and availability
